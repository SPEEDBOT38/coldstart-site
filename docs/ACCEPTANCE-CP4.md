## What the local evidence does and does not show
- Test A: `scripts/verify-store.mjs --backend sqlite` passes all 7 checks (100 concurrent increments, one `setnx` winner, exactly 10 of 100 reservations granted against a cap of 10, idempotency, workspace isolation, restart persistence). That proves the script and the SQL on SQLite. It does **not** prove D1 behaviour.
- Test B: the harness `workers/composite/eval/real_photos.py` ran on the repository's one *synthetic* fixture only (protected pixels 480,778, 0 changed, peak RSS 767 MB). Synthetic stress fixtures give IoU 0.98–0.996 except the thin-edge case (IoU 0.179, flagged needs_review). Backgrounds were procedural gradients and are labelled "not AI photography". Packaging text/logo checks remain `unverified`.
- Test C: the pipeline, paging, caching, caps and scheduling are tested with a **mocked X** (`tests/scan-cp4.test.mjs`, Apple brand). No real X response was seen.
- Test D: adapter failure paths (expired token refresh, 401/402/403/429, duplicate content, timeouts, partial failure, designated-account guard, daily cap) are tested with mocks. No post was made.
- Test E: tracking inspection and verification state machine are tested on fixtures. No event reached Meta. "Verified" requires live-mode accepted non-test events; deduplication stays "unconfirmed" without Events Manager diagnostics.
